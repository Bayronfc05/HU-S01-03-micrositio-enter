La conversación entre navegador y servidor

HTTP es el protocolo que define cómo hablan tu navegador (cliente) y un servidor. Tu navegador envía un request (una petición: "dame esta página"), y el servidor contesta con un response que incluye el contenido y un código de estado que resume qué pasó. El método GET pide datos; otros como POST sirven para enviar datos (por ejemplo, un formulario). Es como entrar a un restaurante y pedirle al mesero un plato específico del menú: tu pedido es el request, lo que te trae (o la explicación de por qué no puede) es el response.

Headers reales de mi sitio

Capturé estos headers con curl -I contra mi propio sitio:

Headers de respuesta — bayronfc05.github.io
Header Valor capturado Qué significa
Server GitHub.com Identifica la infraestructura del servidor de origen.
Content-Type text/html; charset=utf-8 Tipo de contenido (HTML) y codificación de caracteres (UTF-8).
Strict-Transport-Security max-age=31556952 HSTS: le ordena al navegador usar solo HTTPS con este sitio durante ~1 año.
Cache-Control max-age=600 El navegador puede reutilizar esta respuesta en caché durante 600 segundos (10 min) sin volver a pedirla.
ETag "6aa9f9bc-689" Identificador único de esta versión del archivo; sirve para validar si cambió y así devolver un 304 en vez de reenviar todo.
X-Served-By cache-bog-skbo2340037-BOG Nodo exacto de la CDN de Fastly que respondió — en este caso, uno en Bogotá, Colombia.
Via 1.1 varnish Confirma que la petición pasó por un proxy/acelerador basado en Varnish antes de llegar a mí.
X-Fastly-Request-ID 0f2d0052f1be5869a97c6d07e379b41e18596505 ID único de esta solicitud dentro de la red de Fastly, útil para rastreo/debug.
Access-Control-Allow-Origin * Permite que cualquier origen (cualquier otro sitio web) pueda pedir este recurso vía CORS.

Dato interesante: el header X-Served-By confirma que la respuesta la atendió un nodo de la CDN de Fastly ubicado en Bogotá (BOG), no un servidor en Estados Unidos — por eso la latencia hacia mi propio sitio es tan baja comparada con otros dominios que sí viajan hasta EE.
